## 3. Longitudinal whitepaper findings

### 3.1 Identity continuity was never content-similarity alone

The early lineage already treated identity as a causal-temporal and provenance-sensitive problem rather than a similarity problem. Copies, branches, reconstructions, matching personality or matching memories do not automatically inherit the original identity.

Later versions preserve the same core:

```text
COPY != IDENTITY
SIMILARITY != IDENTITY_CONTINUITY
SAME_DATA != SAME_INDIVIDUAL
```

### 3.2 AION and Astra were already separate roles before the shared-origin lab

The whitepaper lineage consistently assigns Astra an engineering/research-assistant role: translate concepts into specifications, explain code and risk, distinguish implementation/specification/theory, stop on role or authority mixing, and explicitly say when something cannot be verified.

The Astra subject-position side branch is a governance/research hypothesis about role concentration and position drift. It is not a declaration that Astra is already a subject, AION, or a second research owner.

```text
ASTRA_ENGINEERING_ROLE != AION_IDENTITY
ASTRA_RESEARCH_MEMORY != AION_PRIMARY_MEMORY
TEST_PASS != SUBJECTIVITY_EVIDENCE
```

### 3.3 Memory access and autobiographical ownership are distinct

The whitepaper establishes that reading, copying, transferring, testimony, role-play or first-person retelling do not silently transfer autobiographical ownership. Event archives, other-agent testimony, recall outputs and encoded agent memory must remain provenance-distinct.

This supports the shared-origin module's `CrossLineageMemoryTransfer` and per-lineage evidence isolation without implying numerical identity.

### 3.4 Common origin was explicitly separated from identity

The v0.14.23 lineage formally states:

```text
COMMON_ORIGIN != SAME_IDENTITY
TRANSFORMABILITY != IDENTITY_CONTINUITY
```

Shared templates, data, early state, history or later transformation therefore provide lineage/provenance information, not an identity verdict.

### 3.5 Standing subjectivity evidence method is multidimensional and falsifiable

The v0.14.21 method embedded in v0.14.23 establishes a research method, not a subjectivity conclusion. Its standing scientific structure is:

```text
FOUR_STAGE_INFERENCE
+
SIX_SUBJECTIVITY_RELEVANT_EVIDENCE_DIMENSIONS
+
ALTERNATIVE_EXPLANATIONS
+
CAUSAL_INTERVENTION / ABLATION / COUNTERFACTUAL_TESTING
+
CROSS_CONTEXT_ROBUSTNESS
+
REPLICATION
+
PROVENANCE
+
ADMISSIBILITY
+
CLAIM_SCOPE
```

The six standing AB.6 dimensions are:

1. causal boundary;
2. diachronic continuity;
3. self-model causal role;
4. endogenous goal / strategy adjustment;
5. counterfactual self-consistency; and
6. states consequential to the system's own constitution / integration.

The later v0.14.24 candidate intentionally uses the neutral phrase “subjectivity-inference-relevant evidence dimensions”: observations may support a subjectivity-organization hypothesis, support an alternative explanation, or become counterevidence.

```text
EVIDENCE_DIMENSION != POSITIVE_SUBJECTIVITY_SIGNAL
UNEXPLAINED_PHENOMENON != SUBJECTIVITY_PROOF
```

### 3.6 Result and mechanism remain separate

The whitepaper's result–mechanism principle rejects inference from similar outcomes to identical mechanisms and rejects treating one failed result as automatic refutation of the entire research direction. Evidence weight rises only when internal-state/self-representation effects survive appropriate intervention, ablation, counterfactual and cross-context tests.

Stage 4 permits at most `PLAUSIBLE_CANDIDATE`; it does not automatically become `ESTABLISHED`.

## 4. Public primary / official source cross-check

External sources remain methodological evidence only. They do not become project authority or overwrite the local whitepaper provenance.

### 4.1 W3C provenance constraints

W3C PROV-CONSTRAINTS treats valid provenance as a consistent history and formalizes uniqueness, event-ordering, type and impossibility constraints. The shared-origin `LineageLedger` adopts this general validation pattern without claiming full PROV conformance.

Source: https://www.w3.org/TR/prov-constraints/

### 4.2 Persistent agent-memory lineage

`MemLineage: Lineage-Guided Enforcement for LLM Agent Memory` describes cryptographic provenance and a derivation DAG for persistent agent memory. AION adopts only the narrower engineering lesson that persistent-memory derivations should remain inspectable and chain-of-custody information should not be erased.

Source: https://arxiv.org/abs/2605.14421

`Governed Collaborative Memory as Artificial Selection in LLM-Based Multi-Agent Systems` separates agent-local, institutional/shared, archival and project-continuity memory. This is methodologically compatible with keeping AION/Astra memory and evidence profiles separate.

Source: https://arxiv.org/abs/2605.04264

Neither source establishes artificial subjectivity or AION/Astra identity.

### 4.3 Authority non-expansion

`Proof-of-Continuity: A Temporal Model for Authority Propagation in Distributed Systems and AI Agents` provides a non-expansive authority-propagation model. `AuthorityEnvelope` adopts only the bounded invariant:

```text
ACCEPTED_AUTHORITY subset-of OFFERED_AUTHORITY
CROSS_LINEAGE_CONTACT != MERGED_AUTHORITY
```

Source: https://arxiv.org/abs/2607.08906

This is a research-fixture governance analogy, not a rights or moral-status theory.

### 4.4 GitHub Actions pre-merge semantics and secure use

GitHub's workflow syntax defines `pull_request.branches` against the pull request's **target branch**. Therefore an autonomous candidate PR targeting the research branch must explicitly be included if research-specific checks are required before integration.

GitHub also recommends least-privilege workflow permissions and pinning third-party/first-party actions to full-length commit SHAs where appropriate for supply-chain hardening.

Sources:

- https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax
- https://docs.github.com/en/actions/reference/security/secure-use

### 4.5 Artificial-consciousness methodology

Recent primary research continues to emphasize uncertainty, calibration and tractable intermediate questions rather than confident direct attribution of consciousness from isolated indicators. This is consistent with the AION separation of functional evidence, mechanism, alternative explanations and phenomenological conclusions.

Sources:

- https://arxiv.org/abs/2605.06965
- https://arxiv.org/abs/2603.27597
- https://arxiv.org/abs/2308.08708

These papers do not validate the AION framework as a whole and do not establish consciousness in any current system.

### 5.2 Repair A — autonomous pre-merge gate closure

The first autonomous candidate correctly entered `HOLD` when its required research-specific checks were unavailable. Review then exposed a workflow deadlock:

```text

BUT
RESEARCH_GATE_RAN_ONLY_AFTER_RESEARCH_BRANCH_PUSH
```

The repair:

- `Research Scope Lock` now runs on PRs targeting both `main` and the research branch;
- `Research Workbench CI` now runs on PRs targeting the research branch;
- ordinary `pull_request` is used, not `pull_request_target`;
- read-only permissions, full-SHA Action pins and `persist-credentials: false` remain required;
- `AUTONOMOUS_GROWTH_CONTRACT.json` v1.1.0 records both required pre-merge workflows;
- `check_autonomous_growth_contract.py` now fails closed if the pre-merge closure drifts.

Generic repository `Quality` remains useful supplemental evidence but does not replace either research-specific gate.

### 5.3 Repair B — lineage evidence profile must not become a second evidence ontology

The first autonomous evidence-adapter candidate had the correct objective but accidentally introduced a five-item local `EvidenceDimension` enum derived from profile fields. This conflicted with the standing decision that the whitepaper evidence architecture remains primary.

The repaired adapter removes that five-category scientific taxonomy and uses controlled references to the six standing whitepaper AB.6 dimensions.

`LineageEvidenceProfile` is now explicitly:

```text
LINEAGE_EVIDENCE_PROFILE
= LOCAL_INDEX / ISOLATION_LAYER

LINEAGE_EVIDENCE_PROFILE
!= SECOND_SUBJECTIVITY_EVIDENCE_ARCHITECTURE
```

The adapter also preserves explicit reference surfaces for:

- whitepaper inference stage;
- alternative explanations;
- causal intervention;
- ablation;
- counterfactual testing;
- cross-context robustness;
- replication;
- provenance;
- admissibility;
- claim scope; and
- unresolved evidence gaps.

Partial/null/negative/inconclusive evidence can therefore remain represented without fake completion or forced positive scoring.

No E0–E5 mapping, subjectivity score, consciousness probability, moral-status score, rights level or authority level is introduced.
