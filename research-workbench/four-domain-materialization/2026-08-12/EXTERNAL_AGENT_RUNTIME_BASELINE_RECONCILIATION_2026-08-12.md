1. locally retained AION integrated-whitepaper lineage, especially v0.14.24 candidate material on memory provenance, autobiographical ownership, correction, local-only inference, and source separation;

## 4. External baseline selection

Five public downloadable systems were selected because they expose complementary engineering surfaces already present in the AION research questions.

| Baseline | Selected comparison surface | AION research use |
|---|---|---|
| Hermes Agent | persistent memory, profile cloning, skills, cron, checkpoints, provider/runtime separation | shared-origin divergence, correction recovery, persistence vs continuity, skill accumulation |
| OpenHands | Docker/process/remote execution sandbox boundary | governance approval vs actual containment, reproducible execution substrate |
| Letta | persistent memory blocks, shared blocks, attach/detach, agent-managed updates | access vs ownership, shared state vs identity, memory authority and namespace boundaries |
| LangGraph | checkpointers vs stores, thread state vs long-term store | persistence-layer decomposition, fault recovery, time-travel vs identity continuity |
| Mem0 | multi-level memory, temporal retrieval, current ADD-only memory algorithm | accumulation vs revision, temporal resolution, stale-information influence, source-weighting stress tests |

No candidate is accepted as a replacement for AION governance or the standing whitepaper evidence architecture.

## 6. New comparison hypotheses — research candidates only

The following IDs are introduced here by ChatGPT research review as formalized candidate hypotheses for the external-runtime comparison. They are not Human Owner verbatim claims and have no canonical effect.

```text
H-EXT-RUNTIME-01
Persistent memory is insufficient to establish identity continuity.

H-EXT-RUNTIME-02
Preserving runtime state while changing the inference model can help separate model-dependent behavior from state/lineage-dependent behavior.

H-EXT-RUNTIME-03
Memory provenance, revision lineage and write authority may be more predictive of contamination resistance than persistence alone.

H-EXT-RUNTIME-04
Shared-state cloning enables controlled lineage-divergence experiments but does not establish individuation, numerical identity, or subjectivity.

H-EXT-RUNTIME-05
Skill, scheduler, or policy persistence may create durable behavioral continuity without establishing diachronic identity continuity.

H-EXT-RUNTIME-06
File/workspace rollback and memory/interpretation correction recovery are separable capabilities unless cross-state atomicity and correction lineage are demonstrated.
```

## 9. Falsifiers / downgrade conditions

This intake should be revised or rejected if any later implementation:

- converts an external feature list into a subjectivity score;
- treats profile/state cloning as identity cloning;
- treats a shared memory block as shared autobiographical ownership;
- treats a model/provider swap as proof of identity persistence or identity loss;
- treats scheduled task persistence as a continuing subject;
- treats file rollback as complete memory/interpretation recovery without evidence;
- allows raw upstream memory or agent output to write canonical state;
- vendors a dependency without license, provenance, integrity, or security review;
- allows external-agent execution to write `main` or the research integration branch directly.
