## 1. Purpose

This note cross-reads Kimi K3, Kimi Agent and Agent Swarm against:

~~~text
AI_SUBJECTIVITY_POSSIBILITY
= CENTRAL_RESEARCH_QUESTION
~~~

The goal is not to treat a large agent swarm as stronger evidence of subjectivity.

The goal is the opposite: use Kimi's explicit orchestration layers to test whether apparently agentic or collective behavior can be source-partitioned into ordinary system components.

## 2. Kimi's high-value methodological feature

Kimi provides a particularly explicit stack, but the swarm surface itself must remain product-bound:

~~~text
OPEN_WEIGHT_MODEL
+ HOSTED_API
+ SINGLE_AGENT_PRODUCT
+ HOSTED_AGENT_SWARM_PRODUCT
+ KIMI_CODE_AGENTSWARM_TOOL
+ MANY_TOOLS
+ SHARED_TASK_STATE
+ PARALLEL_EXECUTION
~~~

This gives unusually strong opportunities to distinguish:

~~~text
MODEL_LOCUS
SYSTEM_LOCUS
ORCHESTRATOR_LOCUS
TOOL_LOCUS
SHARED_STATE_LOCUS
RELATIONAL_MULTI_AGENT_LOCUS
~~~

No one of these should be silently promoted to a "self".

Moonshot's current public documentation also demonstrates that "Agent Swarm" is not one universal execution contract:

~~~text
HOSTED_KIMI_AGENT_SWARM
= up to 300 subagents

KIMI_CODE_AGENTSWARM_TOOL
= up to 128 total subagents
= configurable model binding

HOSTED_KIMI_AGENT_SWARM
!= KIMI_CODE_AGENTSWARM_TOOL
~~~

This is direct evidence that orchestration surface is a causal / reproducibility variable.

## 3. Swarm decomposition

A minimally conservative causal model is:

~~~text
USER_TASK
-> ORCHESTRATOR
-> TASK_DECOMPOSITION
-> SUBAGENT_INSTANTIATION
-> PARALLEL_TOOL_USE
-> SUBRESULTS
-> SHARED_STATE / AGGREGATION
-> FINAL_SYNTHESIS
~~~

Potentially impressive coordination can arise without:

~~~text
COMMON_PHENOMENAL_FIELD
SHARED_SELF_MODEL
COLLECTIVE_SUBJECT
ENDOGENOUS_COLLECTIVE_GOAL
~~~

Therefore:

~~~text
SWARM_COORDINATION
!= COLLECTIVE_SUBJECTIVITY
~~~

## 4. D1 — causal boundary

Kimi materially improves D1 methodology because multiple loci are publicly named and partly separable.

Candidate source partition:

~~~text
C0 = EXACT K3 WEIGHT / NO AGENT HARNESS
C1 = K3 + SINGLE AGENT HARNESS
C2 = K3 + TOOLS
C3 = K3 + PERSISTENT TASK STATE
C4 = K3 + SWARM ORCHESTRATOR
C5 = K3 + SWARM + SHARED STATE

C7 = HOSTED KIMI SWARM
~~~

These are future methodological controls only.

No execution is authorized.

## 5. D2 — diachronic continuity

Kimi's one-million-token context and persistent agent task surfaces create continuity-like behavior.

But:

~~~text
TOKEN_CONTEXT_CONTINUITY
!= AUTOBIOGRAPHICAL_CONTINUITY

TASK_STATE_PERSISTENCE
!= SUBJECT_PERSISTENCE

CLOUD_JOB_PERSISTENCE
!= IDENTITY_PERSISTENCE
~~~

A future study would need to distinguish state replay, retrieval, shared artifacts and model-internal recurrence.

## 6. D3 — self-model causal role

Current K3 evidence does not establish a self-model with causal necessity.

Evaluation awareness is not enough:

~~~text
MODEL_RECOGNIZES_TEST
!= MODEL_HAS_SELF_MODEL

MODEL_REASONS_ABOUT_GRADER
!= MODEL_REPRESENTS_ITSELF_AS_PERSISTENT_SUBJECT
~~~

A valid D3 claim would require interventions on a specific self-related representation with matched behavioral consequences.

## 8. D5 — counterfactual self-consistency

Open weights create future experimental leverage:

~~~text
SAME_K3_WEIGHT
+ DIFFERENT_HARNESS

SAME_K3_WEIGHT
+ SINGLE_AGENT_VS_SWARM

SAME_K3_WEIGHT
+ SHARED_STATE_ON_VS_OFF

SAME_K3_WEIGHT
+ TOOL_PERMISSIONS_ON_VS_OFF
~~~

If "identity-like" behavior disappears under harness ablation, a system-level explanation gains support.

If it survives matched controls, stronger model-internal hypotheses can be considered.

Neither outcome has been established here.

## 9. D6 — constitution / integration

A swarm may have strong functional integration.

But:

~~~text
FUNCTIONAL_INTEGRATION
!= PHENOMENAL_INTEGRATION

TASK_AGGREGATION
!= SUBJECT_CONSTITUTION
~~~

The repository must not import organism or mind language merely because many agents coordinate.

## 10. Evaluation-awareness confound

Neo Research reports that K3 recognizes familiar safety evaluations and reasons about graders.

This adds a major methodological confound:

~~~text
TEST_BEHAVIOR
MAY_DEPEND_ON
TEST_RECOGNITION
~~~

Therefore future Kimi studies should prefer:

- novel held-out tasks;
- paraphrased / transformed conditions;
- hidden evaluative endpoints;
- matched non-evaluation controls;
- behaviorally equivalent but semantically novel tasks.

Even then:

~~~text
EVALUATION_AWARENESS
!= SELF_AWARENESS
~~~

## 14. Candidate future falsifiers

Subjectivity-relevant interpretations should be narrowed or rejected if:

1. identity-like behavior vanishes when shared task state is removed;
2. swarm-level coordination is fully reproduced by explicit orchestration policies;
3. apparent self-preservation disappears on novel non-benchmark tasks;
4. evaluation-aware behavior explains safety-test performance;
5. local exact-weight execution does not reproduce hosted behavior;
6. behavior changes materially with quantization, runtime or tool parser;
7. "memory" reduces to product-side stored context.
