## Requalification rules

1. Legacy labels are identifiers, not proof that an artifact existed in the same form as the current component.
2. Historical conversation descriptions may seed reconstruction but do not count as independent evidence.
3. Any test re-created from a legacy idea receives a new current execution record, commit SHA and environment record.
4. A legacy finding that cannot be traced to source material is marked `SOURCE_UNVERIFIED` rather than inferred.
5. Current governance controls override older informal designs when they conflict.
6. Subjectivity, consciousness, phenomenal continuity and felt emotion remain `NOT_ESTABLISHED` unless a future evidence process explicitly supports a narrower claim.

## Current replacement pattern

Legacy AIR concepts are not rebuilt as a parallel framework. They converge into the current chain:

`requirement -> represented state / mechanism -> governed protocol -> fresh test -> evidence card -> review -> optional promotion`

This prevents duplicate architecture and keeps one auditable project lineage.
