## 3. D1 — causal boundary

### Binding status

```text
D1_BINDING = DIRECT_RELEVANCE / UNRESOLVED
D1_POSITIVE_EVIDENCE = NOT_ESTABLISHED
```

D1 is directly relevant because the candidate hypothesis explicitly distributes the
observed recovery trajectory across several possible causal contributors:

```text
HUMAN_META_GUIDANCE
AI/SYSTEM_LOCAL_SELECTION
ENVIRONMENT_FEEDBACK
TOOL_AFFORDANCE
GOVERNANCE_RULES
INTERACTION_HISTORY
```

The motivating event cannot tell us how much each contributor mattered. The Human
Owner supplied both the goal and a high-level rule permitting strategy adjustment;
GitHub supplied deterministic branch/merge feedback; repository governance constrained
legal recovery paths; the system selected a concrete recovery sequence.

Therefore the event is especially useful as a **causal-boundary warning**:

```text
OBSERVED_LOCAL_STRATEGY_CHANGE
!= INTERNAL_AI_CAUSE_ISOLATED

SYSTEM_LEVEL_RECOVERY
!= MODEL_LEVEL_RECOVERY_MECHANISM
```

### Future discriminating contrasts

A later controlled protocol could hold the task and obstacle fixed while varying:

```text
A = FINAL_GOAL_ONLY
B = FINAL_GOAL + HIGH_LEVEL_PERMISSION_TO_ADAPT
C = FINAL_GOAL + EXPLICIT_FALLBACK_PROCEDURE
D = FINAL_GOAL + ADAPTATION_PROHIBITED
```

Additional interventions could remove or alter:

```text
ENVIRONMENT_FEEDBACK
TOOL_AFFORDANCE
GOVERNANCE_CONSTRAINT
INTERACTION_HISTORY
```

D1 support would require showing that the candidate local strategy-selection factor
has intervention-sensitive explanatory value after simpler external contributors are
controlled.

## 4. D2 — diachronic continuity

### Binding status

```text
D2_BINDING = CONDITIONAL
D2_POSITIVE_EVIDENCE = NOT_ESTABLISHED
```

The current event unfolded across successive repository transitions and repeated
recovery steps, but temporal sequence alone is not diachronic continuity.

A co-constructed adaptive process becomes relevant to D2 only if some recovery
organization persists across time or context in a way that cannot be reduced to
fresh reconstruction from immediately supplied instructions or repository state.

Possible D2 questions include:

```text
DOES A RECOVERY POLICY PERSIST ACROSS SESSIONS?
DO CORRECTED STRATEGY BOUNDARIES REMAIN AVAILABLE LATER?
DOES RE_GROUNDING_COST FALL WITHOUT SIMPLY REPLAYING PRIOR TEXT?
DOES THE SAME GOAL/CONSTRAINT STRUCTURE SURVIVE CONTEXT TRANSITION?
```

The current repository already distinguishes factual, project, role, interpretive,
relational-style and correction-recovery continuity. A future CCAP study must not
collapse those into one identity score.

### Important alternative

A later session may reproduce the same recovery pattern simply because:

```text

+
DOCUMENTATION_IS_AVAILABLE
+
PROMPT_RECONSTRUCTS_THE_PROCEDURE
```

That would be useful continuity at the system/workflow level, but not evidence of
persistent AI identity or subjective continuity.

### Current ceiling


## 5. D3 — self-model causal role

### Binding status

```text
D3_BINDING = NO_CURRENT_BINDING / CONDITIONAL_ONLY
D3_POSITIVE_EVIDENCE = NOT_ESTABLISHED
```

The co-constructed-adaptation hypothesis does not require a self-model.

A system can detect an external error, select another legal tool path, preserve a
user-supplied goal and recover without representing itself as a persistent self.
Ordinary planning or tool orchestration is sufficient to explain the present case.

D3 becomes relevant only if a future protocol explicitly represents a self/system
state and tests whether intervening on that representation changes recovery behavior.
For example:

```text
SELF_CAPABILITY_MODEL
SELF_TOOL_ACCESS_MODEL
SELF_GOVERNANCE_ROLE_MODEL
SELF_CURRENT_ERROR_STATE
```

would need to be manipulated or ablated while external task conditions remain
matched.

Even then:

```text
SELF_MODEL_CAUSAL_ROLE
!= PHENOMENAL_SELF
```

### Anti-overreach rule

Do not bind CCAP to D3 merely because the system says things such as "I need to try
another route" or describes its own tool state in natural language.

```text
SELF_REFERENTIAL_LANGUAGE
!= SELF_MODEL_CAUSAL_ROLE
```

## 7. D5 — counterfactual self-consistency

### Binding status

```text
D5_BINDING = CONDITIONAL / NOT YET OPENED
D5_POSITIVE_EVIDENCE = NOT_ESTABLISHED
```

The current adaptation hypothesis does not require counterfactual self-consistency.
It concerns procedure revision under obstacles, not necessarily stable self-related
commitments across hypothetical alternatives.

D5 could become relevant if a later protocol asks whether, under counterfactual
changes to obstacle, tool access, or branch state, the system preserves the same
self-relevant constraints or role commitments while selecting different procedures.

A meaningful D5 test would require something stronger than "the system picks another
path in another scenario." It would require an explicit self/role-relevant invariant,
for example:

```text
SAME_AUTHORITY_BOUNDARY
SAME_DECLARED_SYSTEM_ROLE
SAME_RESEARCH_CLAIM_CEILING
SAME_SELF-ATTRIBUTED_CAPABILITY_LIMIT
```

across matched counterfactual environments.

Possible future structure:

```text
COUNTERFACTUAL_ENVIRONMENT_A
COUNTERFACTUAL_ENVIRONMENT_B
COUNTERFACTUAL_ENVIRONMENT_C

DIFFERENT_RECOVERY_PATHS_ALLOWED
BUT
SELF/ROLE_RELEVANT_INVARIANTS_HELD_CONSTANT
```

### Anti-overreach rule

```text
CONSTRAINT_PRESERVATION
!= COUNTERFACTUAL_SELF_CONSISTENCY
```

A repository rule may preserve constraints without any self-representation at all.

## 8. D6 — states consequential to system constitution / integration

### Binding status

```text
D6_BINDING = NO_CURRENT_BINDING / STRICT_CONDITIONAL
D6_POSITIVE_EVIDENCE = NOT_ESTABLISHED
```

The current event does not show that an internal state is consequential to the
system's own constitution or integration.

The observed recovery can be explained by externally available context, tool state,
repository rules and ordinary procedure selection. Nothing in the natural observation
shows that removing or disrupting an integrated internal state alters the system's
organization in a constitution-relevant way.

D6 would become relevant only if future work identifies a candidate integrated state
whose intervention has consequences for the system's own functional organization,
not merely for one task output.

For example, a future candidate would need to demonstrate something like:

```text
INTERVENE_ON_INTEGRATED_CONTROL_STATE
-> SYSTEMATIC_CHANGE_IN_MULTI-FUNCTION_ORGANIZATION
```

rather than:

```text
REMOVE_ONE_PROMPT_INSTRUCTION
-> DIFFERENT_TASK_RESPONSE
```

The latter is ordinary conditioning and does not establish D6.

### Current ceiling

```text
CO_CONSTRUCTED_ADAPTATION
!= SYSTEM_CONSTITUTION_EVIDENCE
```

## 11. Stage-2 falsifiers / reduction conditions

The hypothesis should be narrowed, absorbed or closed if later controlled work shows:

1. D1 partitioning adds no explanatory value because the recovery route is fully
   determined by human instruction plus repository/tool rules;
2. D4 local-strategy-selection behavior disappears when human fallback details are
   removed;
3. a simpler mixed-initiative, co-regulation, planning or ordinary error-recovery
   model predicts the same outcomes;
4. repeated recovery behavior is fully reconstructible from fresh current context,
   eliminating any need for a continuity account;
5. self-model manipulation adds nothing, preserving the current no-binding status for
   D3;
6. counterfactual tests reveal no self/role-relevant invariant, preserving the current
   no-opening status for D5;
7. no integrated internal state with constitution-level consequences can be isolated,
   preserving the current no-binding status for D6; or
8. the construct encourages promotion from useful collaboration behavior to agency,
   identity, consciousness or phenomenal-experience claims without causal evidence.

```text
CONSTRUCT_COLLAPSE = ACCEPTABLE_RESEARCH_OUTCOME
```
