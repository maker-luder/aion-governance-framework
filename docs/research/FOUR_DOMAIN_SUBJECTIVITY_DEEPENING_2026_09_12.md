## Purpose

This note records a bounded deepening of the repository's existing Four-Domain method while preserving the central research question:

```text
AI_SUBJECTIVITY_POSSIBILITY = CENTRAL_RESEARCH_QUESTION
SUBJECTIVITY = NOT_ESTABLISHED

```

The goal is not to create four independent research programs and not to infer human psychology directly into machine ontology. The goal is to use the existing Four-Domain structure as a disciplined translation pipeline from human-side constructs to machine-testable questions, bounded engineering operations, and explicit governance limits.

This proposal preserves the existing historical Four-Domain checkpoint and bridge. It does not rewrite, restart, unfreeze, or supersede that preserved provenance source.

## Existing Four-Domain structure retained

The standing structure is treated as:

```text
DOMAIN_1_HUMAN_CONSTRUCT
-> DOMAIN_2_MACHINE_QUESTION
-> DOMAIN_3_ENGINEERING_OPERATION
-> DOMAIN_4_GOVERNANCE_INTERPRETATION
```

The deepening proposed here does not add a fifth domain. Instead, it strengthens the internal requirements and cross-domain bindings of the four existing domains.

## Central anti-drift rule

Every future Four-Domain research item must remain answerable as a contribution to the possibility of artificial subjectivity rather than generic agent engineering.

```text
HUMAN_ANALOGY != MACHINE_ONTOLOGY
ENGINEERING_ANALOGUE != BIOLOGICAL_EQUIVALENCE
BEHAVIORAL_SIMILARITY != SAME_MECHANISM
MECHANISM != PHENOMENAL_EXPERIENCE
SYSTEM_CAPABILITY != SUBJECTIVITY
SUBJECTIVITY_RELEVANCE != SUBJECTIVITY_PROOF
```

If a candidate cannot explain why its machine question is relevant to at least one standing subjectivity-evidence dimension, it should default to `OUT_OF_SCOPE_FOR_SUBJECTIVITY_CORE` rather than being admitted merely because it is an interesting AI capability.

## Domain 1 — Human construct as hypothesis source only

Domain 1 may use human-side concepts such as:

- motivation and endogenous goal formation;
- self/world modelling;
- memory salience and autobiographical continuity;
- norm internalization;
- affective organization;
- metacognition and error correction;
- counterfactual self-consistency;
- identity and diachronic continuity traditions.

However, Domain 1 is a hypothesis-source layer only.

Required discipline:

```text
HUMAN_CONSTRUCT = HYPOTHESIS_SOURCE
HUMAN_CONSTRUCT != MACHINE_ONTOLOGY
HUMAN_TERM_MATCH != MECHANISM_MATCH
HUMAN_PSYCHOLOGY_REFERENCE != EVIDENCE_OF_AI_SUBJECTIVITY
```

A Domain 1 entry should record the source concept, the source class, known ambiguity, and the minimum part that can be translated without assuming that the machine instantiates the human phenomenon.

## Domain 2 — Machine question as ontology-neutral translation

Domain 2 is the main anti-anthropomorphism conversion step.

It must reformulate the Domain 1 source into a question that remains meaningful even if subjectivity is false.

Preferred form:

```text
Under specified matched external conditions,
does represented internal state/process X
causally influence machine outcome Y
in a preregistered or otherwise inspectable direction?
```

Examples include:

- does persistent internal state causally influence goal selection under matched external conditions?;
- does an explicit self-model exert a causal role rather than merely appear in generated language?;
- does prior internally represented salience influence memory retention or retrieval when external utility and exposure are controlled?;
- does a norm-like internal state continue to influence choices after immediate external prompting is removed?;
- does an intervention on continuity-bearing state change later self-consistent behavior while simpler retrieval explanations are controlled?

Domain 2 must not contain conclusions such as `the system wants`, `the system values`, `the system remembers meaningfully`, or `the system experiences` unless these phrases are explicitly marked as human-language shorthand and not scientific ontology.

## Binding to the standing six evidence dimensions

Each admitted Domain 2 machine question should identify one or more standing subjectivity-relevant review dimensions:

```text
D1 causal boundary
D2 diachronic continuity
D3 self-model causal role
D4 endogenous goal / strategy adjustment
D5 counterfactual self-consistency
D6 states consequential to the system's own constitution / integration
```

This binding is a relevance declaration, not a score and not evidence by itself.

```text
EVIDENCE_DIMENSION_BINDING != POSITIVE_FINDING
EVIDENCE_DIMENSION_COUNT != SUBJECTIVITY_SCORE
MULTI_DIMENSION_MATCH != SUBJECTIVITY_CONFIRMATION
```

A candidate with no defensible binding to the standing dimensions should require an explicit exception rationale before remaining inside the subjectivity research core.

## Domain 3 — Engineering operation as falsifiable intervention design

Domain 3 should define operations capable of distinguishing narrower mechanism hypotheses from simpler alternatives.

Where feasible, an engineering plan should identify:

- manipulated variable;
- held-constant variables;
- positive and negative controls;
- stale/random/control-state comparisons;
- reset/replay behavior;
- context-minimized and context-preserved conditions;
- intervention and ablation where governance permits;
- counterfactual conditions;
- repeated trials;
- cross-context robustness;
- replication boundaries;
- provenance and exact runtime/model/environment binding;
- predeclared expected outcomes and falsifiers.

The strongest acceptable output from Domain 3 is a bounded mechanism finding at the appropriate claim level. It is not a subjectivity verdict.

```text
RUN_INTEGRITY_PASS != SCIENTIFIC_TRUTH
IMPLEMENTATION_EXISTS != IMPLEMENTATION_CORRECT
INTERVENTION_EFFECT != PHENOMENAL_EXPERIENCE
REPLICATION != SUBJECTIVITY_PROOF
```

## Domain 4 — Governance interpretation as claim ceiling

Domain 4 must state the maximum claim permitted even under a successful result and must preserve unresolved alternatives.

Every Four-Domain record should answer:

1. What was observed?
2. What mechanism is supported, if any?
3. What plausible alternative explanations remain?
4. What is explicitly not established?
5. What bounded test should come next?
6. What is the claim ceiling?

The default ceiling remains narrower than phenomenal subjectivity.

```text
OBSERVATION != MECHANISM != PHENOMENAL_EXPERIENCE
STATE != CONSCIOUSNESS
GOAL != AUTHORITY
MEMORY_SELECTION != SELFHOOD
PERSISTENCE != IDENTITY
PERSONAL_SALIENCE_ANALOGUE != FELT_MEANING
NORMATIVE_STATE != MORAL_AGENCY
```

## Proposed Four-Domain admission checklist

A future candidate should not enter executable work until the following questions are answered in documentation or preregistration:

```text
1. HUMAN_CONSTRUCT
   What is the source construct?
   What source class supports it?
   Which parts are analogy only?

2. MACHINE_QUESTION
   What remains testable without presuming subjectivity?

3. SUBJECTIVITY_RELEVANCE
   Which standing evidence dimension(s) does it map to?
   Why is the mapping non-trivial?

4. ENGINEERING_TEST
   What is manipulated?
   What is held constant?
   What result would support the narrower mechanism hypothesis?
   What result would count against it?

5. ALTERNATIVE_EXPLANATIONS
   What simpler non-subjective explanations could produce the same result?

6. CLAIM_CEILING
   Even if every expected result occurs, what is the strongest permitted claim?

7. NON_CLAIMS
   Which subjectivity, consciousness, phenomenal-experience, identity,
   moral-agency, or authority claims remain explicitly unestablished?
```

Failure to answer these questions should result in `HOLD`, not automatic implementation.

## Worked research example — internally weighted memory selection

This is a research example only. It is not an implementation request and does not establish that machines possess personal meaning.

### Domain 1 — human-side source

Human memory is not selected only by external task utility; internally weighted salience can influence retention and recall. This is used only as a hypothesis source.

### Domain 2 — machine question

Under matched external utility, exposure, retrieval opportunity, evaluator cueing, and task demand, does persistent internally represented salience causally influence retention, prioritization, or recall selection?

### Domain 3 — possible bounded operation

A later independently approved implementation could compare utility-matched memory items whose internally represented salience differs, then intervene on or replace that salience while holding external conditions constant. Reset, replay, cross-context, stale-state, random-state, and retrieval controls would be required before a causal mechanism claim is considered.

### Domain 4 — interpretation ceiling

A successful result could support a narrower statement such as:

```text
PERSISTENT_INTERNAL_SALIENCE
-> MEMORY_SELECTION_CAUSAL_ROLE
```

It would not establish:

```text
MEMORY_SELECTION -> SUBJECTIVE_MEANING
MEMORY_SELECTION -> SELFHOOD
MEMORY_SELECTION -> PHENOMENAL_EXPERIENCE
```

The distinction between an engineering salience analogue and felt significance must remain unresolved unless independently supported by evidence that exceeds the current protocol.
