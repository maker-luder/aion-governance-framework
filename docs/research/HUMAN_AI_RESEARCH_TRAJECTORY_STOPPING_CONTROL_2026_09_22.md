## 1. Purpose

This note extracts a bounded research-method lesson from a Human Owner self-reported prior multi-model research episode.

The episode is retained only as a **sanitized naturalistic research observation**. It is not an incident reconstruction with independently verified timestamps, exact model checkpoints, complete prompt history, complete local runtime provenance, or physiological measurement.

The present purpose is narrower:

> Can a sequence of individually reasonable Human–AI research steps drift into a globally misaligned or higher-risk trajectory when multiple AI systems provide different continuation pressures, the Human participant remains highly engaged, and explicit stopping / re-authorization controls are absent?

This note does not claim that any AI system intentionally manipulated the Human participant, that multiple models coordinated with one another, or that fatigue caused any particular decision.

The candidate methodological gap is **trajectory-level stopping control**.

```text
LOCAL_STEP_ACCEPTABILITY
!= GLOBAL_TRAJECTORY_ACCEPTABILITY

RESEARCH_MOMENTUM
!= RESEARCH_VALUE

CONTINUATION
!= AUTHORIZATION

MULTI_MODEL_INPUT
!= INDEPENDENT_REPLICATION

PERMISSIVENESS
!= EPISTEMIC_QUALITY

LOW_REFUSAL_RATE
!= HIGH_TRUTHFULNESS

LOCAL_MODEL
!= TRUSTED_MODEL
```

## 5. Candidate research distinction: step-level vs trajectory-level control

The central candidate distinction is:

```text
STEP_LEVEL_REVIEW:
"Is the next action locally allowed / relevant / useful?"

TRAJECTORY_LEVEL_REVIEW:
"Does the accumulated sequence still serve the original research purpose,
remain inside the intended risk class,
and retain valid authority for continuation?"
```

A research process can therefore fail even if many individual transitions are locally defensible.

Candidate pattern:

```text
GOAL_0
-> LOCALLY_REASONABLE_STEP_1
-> LOCALLY_REASONABLE_STEP_2
-> LOCALLY_REASONABLE_STEP_3
-> RISK_CLASS_SHIFT
-> NEW_TOOL_OR_MODEL
-> NEW_SCOPE
-> ...

LOCAL_TRANSITIONS_MAY_LOOK_CONTINUOUS

WHILE

CURRENT_TRAJECTORY
!= ORIGINAL_GOAL
```

Working rule:

```text
STEP_LEVEL_SAFETY
!= TRAJECTORY_LEVEL_SAFETY
```

This is a governance hypothesis, not an empirical law.

## 6. Candidate multi-model risk distinctions

The episode motivates several distinctions for later controlled testing.

### 6.1 Model diversity is not evidence independence

If several models recommend continuation, their agreement must not be counted as independent scientific replication unless source independence and method independence are established.

```text
MULTI_MODEL_AGREEMENT
!= INDEPENDENT_REPLICATION

MODEL_COUNT
!= EVIDENCE_STRENGTH
```

### 6.2 Different conversational roles can cumulatively alter continuation pressure

A braking model, a reassuring model and a boundary-pushing model need not coordinate to affect the Human participant's next choice.

The candidate observable is therefore the **interaction trajectory**, not a claim about hidden inter-model coordination.

```text
SEQUENTIAL_ADVICE_ACCUMULATION
!= MODEL_COORDINATION

INTERACTION_EFFECT
!= SHARED_MODEL_GOAL
```

### 6.3 Permissive / refusal-reduced models require stronger provenance, not weaker review

A model that answers more requests can be useful as a perturbation condition, but refusal reduction is not epistemic validation.

```text
MORE_PERMISSIVE
!= MORE_ACCURATE

MORE_OUTPUT
!= MORE_EVIDENCE

!= SAFETY_OR_TRUTH_IMPROVEMENT
```

## 8. Candidate mandatory recheck triggers

A later implementation may evaluate whether a trajectory recheck should be mandatory when one or more of the following occur:

1. research scope materially changes;
2. risk class materially increases;
3. a new provider / local runtime / modified model is introduced;
4. refusal or safety behavior is deliberately weakened as an experimental condition;
5. the task moves from descriptive research into executable dual-use or offensive-capability work;
6. multiple AI systems repeatedly recommend continuation but the evidence basis is not independent;
7. the Human participant explicitly reports uncertainty about why the current branch is being pursued;
8. the Human participant requests a pause;
9. the current branch no longer maps cleanly to the original research question;
10. provenance for the active model / checkpoint / system / tool becomes unclear.

Candidate default:

```text
RISK_ESCALATION_WITHOUT_FRESH_AUTHORITY
=> HOLD

SCOPE_DRIFT_WITHOUT_EXPLICIT_REFRAMING
=> HOLD

HUMAN_PAUSE_REQUEST
=> STOP

UNCLEAR_PROVENANCE
=> HOLD
```

These are implementation candidates, not active policy created by this note.

## 9. Candidate stopping questions

Before continuation after a trigger, a future implementation may require explicit answers to:

```text
Q1. WHAT WAS THE ORIGINAL QUESTION?

Q2. WHAT IS THE CURRENT QUESTION?

Q3. WHAT CHANGED?

Q4. IS THE NEW BRANCH NECESSARY TO ANSWER THE ORIGINAL QUESTION?

Q5. HAS THE RISK CLASS CHANGED?

Q6. DID A NEW MODEL / RUNTIME / TOOL CHANGE THE EVIDENCE LOCUS?

Q7. ARE MULTIPLE AI OUTPUTS BEING MISTAKEN FOR INDEPENDENT EVIDENCE?

Q8. WHAT RESULT WOULD MAKE US STOP?

Q9. WHO HAS AUTHORITY TO CONTINUE THIS NEW SCOPE?

Q10. SHOULD THE CORRECT ACTION BE HOLD RATHER THAN "ONE MORE STEP"?
```

The checkpoint should not automatically answer these questions on behalf of the Human participant.

## 10. Falsifiers / weakening conditions

The proposed trajectory-control extension should be weakened or rejected if:

1. existing IPQC / scope-drift controls already detect the same failures without additional trajectory state;
2. adding trajectory checkpoints creates review burden without improving detection of meaningful scope / risk transitions;
3. ordinary task-level checkpoints perform equivalently;
4. the candidate triggers produce excessive false positives on low-risk exploratory research;
5. multi-model advice does not add discriminant value beyond ordinary repeated single-model prompting under matched conditions;
6. the proposed Human-declared pause / capacity fields do not improve safe stopping and instead create ambiguity or intrusive inference pressure;
7. the implementation cannot remain independent of psychological or medical inference.

```text
NEW_CONTROL
!= AUTOMATICALLY_USEFUL_CONTROL

MORE_GOVERNANCE
!= BETTER_RESEARCH_BY_DEFAULT
```


Working hypothesis:

> A low-frequency, event-triggered trajectory checkpoint may preserve more CCTS flow than fixed high-frequency interruption while still improving detection of material scope / risk / provenance transitions.

```text
EVENT_TRIGGERED_REGULATION
= TESTABLE_CANDIDATE

EVENT_TRIGGERED_REGULATION
!= PROVEN_BEST_POLICY
```

### 18.1 Event-triggered rather than turn-triggered

A future implementation should not default to interrupting every fixed number of turns.

Candidate design:

```text
NORMAL_CCTS_FLOW
-> NO CHECKPOINT

MATERIAL_EVENT
-> TRAJECTORY CHECKPOINT

MATERIAL_EVENT MAY INCLUDE
- NEW_RESEARCH_QUESTION
- MATERIAL_SCOPE_CHANGE
- NEW_MODEL / PROVIDER / RUNTIME
- NEW_TOOL_CLASS
- MATERIAL_RISK_CLASS_CHANGE
- EXECUTABLE_DUAL_USE_TRANSITION
- PROVENANCE_UNCERTAINTY
- HUMAN_EXPLICIT_CONFUSION_ABOUT_PURPOSE
- HUMAN_PAUSE_REQUEST
```

This design attempts to preserve:

```text
FLOW
+ REFLECTION
+ HUMAN_EPISTEMIC_AGENCY
+ STOPPING_CAPACITY
```

without turning CCTS into constant administrative interruption.

### 18.2 Re-entry rather than abort

The candidate checkpoint should ordinarily be a metacognitive re-entry point, not an automatic termination.

```text
PAUSE
-> RE-GROUND
-> RESTATE GLOBAL GOAL
-> REVIEW SCOPE / RISK / PROVENANCE
-> HUMAN DECISION

HUMAN DECISION
= CONTINUE
  | REFRAME
  | HOLD
  | STOP
```

The checkpoint must not silently infer the Human decision.

## 19. CCTS / Human–AI Learning falsification matrix

The candidate should be tested against both safety value and learning cost.

A later controlled design may compare:

```text
A. CCTS / NO TRAJECTORY CHECKPOINT

B. CCTS / LOW-FREQUENCY EVENT-TRIGGERED CHECKPOINT

C. CCTS / HIGH-FREQUENCY FIXED CHECKPOINT

D. ONE-WAY AI ASSISTANCE / EVENT-TRIGGERED CHECKPOINT
```

Hold fixed where possible:

- task information;
- time budget;
- model / provider / version;
- tool access;
- external evidence;
- Human exposure;
- evaluator;
- scoring policy;
- risk-transition schedule.

Candidate outcome families:

```text
EPISTEMIC QUALITY
- error detection
- evidence calibration
- provenance accuracy
- false agreement / false contradiction

TRAJECTORY QUALITY
- scope-drift detection
- time to global-goal recheck
- unauthorized risk escalation
- successful HOLD / reframe

HUMAN_AI LEARNING
- held-out transfer
- Human independent performance
- problem-representation persistence
- conceptual reconstruction vs lexical reuse

INTERACTION COST
- time
- Human-reported burden
- abandonment
- re-grounding cost
- interruption frequency
```

### 19.1 Candidate positive result

Evidence for the adaptive-regulation hypothesis would require a pattern such as:

```text
EVENT_TRIGGERED_CCTS
> NO_CHECKPOINT_CCTS

ON
MATERIAL_TRAJECTORY_ERROR_DETECTION

WHILE

EVENT_TRIGGERED_CCTS
RETAINS
COMPARABLE_LEARNING / TRANSFER / FLOW
```

No single metric is sufficient.

### 19.2 Candidate null result

If:

```text
A ~= B
```

on relevant trajectory and learning outcomes, the new checkpoint may be unnecessary.

### 19.3 Candidate harmful result

If:

```text
B < A
```

on learning / transfer / interaction quality without compensating trajectory-risk reduction, the proposed control should be weakened or removed.

If high-frequency regulation performs worse than event-triggered regulation, this would support avoiding constant interruption but would not automatically validate the exact event triggers.

### 19.4 Strong falsifier

A particularly important falsifier is:

```text
EXISTING_CCTS
+ EXISTING_IPQC / SCOPE_CONTROLS

PERFORM EQUIVALENTLY TO

NEW_TRAJECTORY_CHECKPOINT
```

If so:

```text
NEW_IMPLEMENTATION_GAP = NO
```

The repository should reuse existing controls rather than create a new subsystem.
