## 1. Purpose

This note records a longitudinal Human–AI research observation about explicit personalization / interaction rules as a versioned collaboration artifact.

The observation arose from repeated revisions of interaction rules across prior sessions and from a 2026-09-27 comparison between:

1. a research-oriented Human–AI collaboration using explicit provenance, evidence, recovery, learning, and role-boundary rules;
2. a separate creative image-generation use case described by the Human, which appears to rely on a much smaller set of high-level global constraints plus local iterative feedback; and
3. an established cross-domain writing practice in which the Human requires an explicit, inspectable "reader manual" separating calculation rules, interpretation rules, and verification boundaries.

The note asks whether explicit personalization artifacts can serve as a bounded operational surface for studying some CCTS-relevant processes.

## 4. Local L0-L4 working schema

The hierarchy below is repository-local and provisional. It is not presented as an established external taxonomy.

```text
L0 = CORE OBJECTIVE
     why the collaboration policy exists

L1 = META-POLICY
     high-level governance or interaction policy

L2 = SUB-POLICY
     decision principle under an L1 policy

L3 = OPERATIONAL RULE
     concrete condition/action rule

L4 = CASE / EXAMPLE
     bounded instance showing application
```

Example:

```text
L0
HIGH-INTEGRITY LONGITUDINAL HUMAN-AI COLLABORATION

  -> L1 TRUTH CALIBRATION
       -> L2 evidence/claim separation
            -> L3 EVIDENCE != PROOF
                 -> L4 one bounded research case

  -> L1 FAILURE RECOVERY
       -> L2 unknown-result recovery
            -> L3 UNKNOWN_RESULT -> READ LIVE STATE BEFORE RETRY
                 -> L4 one bounded repository interruption case
```

The hierarchy is a representation device. Its existence does not establish that the policy is effective.

### 5.1 Hierarchical Task Analysis (HTA)

The U.S. Agency for Healthcare Research and Quality describes Hierarchical Task Analysis as decomposing an overall goal into subgoals, operations, and plans until an appropriate operational level is reached.

Source:

- https://digital.ahrq.gov/health-it-tools-and-resources/evaluation-resources/workflow-assessment-health-it-toolkit/all-workflow-tools/hierarchical-task-analysis

Permitted correspondence:

```text
OVERALL_GOAL -> SUBGOALS -> OPERATIONS
~ L0 -> L1/L2 -> L3
```

Boundary:

```text
L0_L4_SCHEMA != HTA_STANDARD
```
