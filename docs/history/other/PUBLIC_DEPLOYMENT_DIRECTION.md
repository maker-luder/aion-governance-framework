# Public deployment direction

Owner direction recorded for the post-RC implementation branch on 2026-08-07.

## Active direction

- Make AION/Astra deployable through a documented, self-hostable path.
- Keep governance gates, explicit human approval, provenance and audit as deployment invariants.
- Add a public feedback channel using the repository issue form; submissions are public and must not contain secrets or private project data.
- Implement a persistent cross-session memory store behind identity, access, provenance and conflict gates. Persistence does not equal canonical truth.
- Advance the canonical AION Runtime as an implementation candidate. Canonical promotion still requires Owner review and validation evidence.
- Prepare an IV&V evidence packet, without claiming independent IV&V has occurred.
- Permit engineering of the non-3D twin-genesis embodiment Runtime candidate while keeping 3D assets deferred.

## Explicitly held

- Sexual-function or intimate-interaction research remains NOT_AUTHORIZED.
- Controlled/random ablation execution is not exposed in the public deployment path and remains held.
- Formal G1 benchmarking requiring adequate hardware and real LoRA training remain hardware-deferred.
- 3D embodiment assets remain deferred.

## Deployment boundary

Public deployment does not mean unrestricted execution. A deployable release must preserve:

1. explicit operator/Owner approval for state-changing actions;
2. no relationship- or familiarity-derived privileges;
3. no automatic canonical writeback;
4. separate AION/Astra identity and memory namespaces;
5. auditable runtime decisions and memory provenance;
6. no public exposure of credentials, private memory, private conversation history, or restricted source material;
7. ablation and experimental high-impact controls disabled unless separately admitted.

## License dependency

The repository can be publicly viewable and the project owner can deploy it before choosing an open-source license. However, a third party needs an actual redistribution/use license if the intended public deployment model is "clone, modify, redistribute, and self-host." License selection is therefore a release-governance dependency, not a hardware dependency.
