# Roadmap After Public RC

The first public RC remains frozen as historical release evidence. New work proceeds additively after that baseline and must not rewrite the RC's validation claims.

Owner direction recorded 2026-08-07 separates items that are hardware-blocked from items that can advance in software or governance work.

| Item | Status | Current direction |
|---|---|---|
| Formal G1 baseline on adequate hardware | HARDWARE_DEFERRED | Hold until adequate benchmark hardware is available |
| Real LoRA training | HARDWARE_DEFERRED | Hold |
| Controlled and random ablation execution | GOVERNANCE_HOLD | Do not expose or execute in the new public deployment path yet |
| Canonical AION Runtime | IMPLEMENTATION_ACTIVE | Build as an implementation candidate; canonical promotion requires Owner review and validation |
| Live cross-session memory | IMPLEMENTATION_ACTIVE | Add persistent store behind identity/access/provenance/conflict/writeback gates; no automatic canonical effect |
| Public / self-host deployment | IMPLEMENTATION_ACTIVE | Prioritize documented AION/Astra deployment while retaining governance boundaries |
| Public feedback channel | IMPLEMENTATION_ACTIVE | Use a public GitHub issue form; no secrets/private data |
| Independent IV&V | PREPARE_EVIDENCE_ONLY | Prepare evidence/index material; do not claim IV&V achieved |
| Twin-genesis embodiment Runtime | IMPLEMENTATION_ALLOWED_NON_3D | Runtime candidate may advance; 3D assets remain deferred |
| 3D embodiment assets | HARDWARE_SCOPE_DEFERRED | Hold |
| Sexual-function or intimate-interaction research | NOT_AUTHORIZED | Hold; no implementation or public exposure |
| License selection | OWNER_DECISION_REQUIRED | No license chosen on this branch; verify compatibility before changing repository-wide rights |

New proposals must record source, rationale, risk and dependencies. Work that changes canonical state, deployment authority, memory writeback, licensing, or research authorization still requires explicit Owner review.
