# AION Native Language Semantic Model v0.1.0

**Status:** `ESTABLISHED_CANDIDATE / NON_EXECUTABLE`

**Language category:** constrained declarative semantic DSL

**Language version:** `0.1`

**Semantic IR version:** `0.1.0`

**Canonical effect:** `NONE`

## 1. Model boundary

This model describes a source notation, syntax-derived AST, static semantic analysis, and validated semantic IR. It intentionally does not describe a runtime executor. Its purpose is to make AION-specific requirements explicit, deterministic, reviewable, and portable across future parser implementations.

```text
AION Native Source
      │ parse
      ▼
Syntax-derived AST
      │ static semantic analysis
      ▼
Validated AION Semantic IR
      │ future, separately authorized adapters only
      ▼
External governed runtime admission
```

Every arrow is a distinct boundary. Source does not create authority. AST does not create authority. Validated IR does not create authority. Runtime admission must use external governed evidence for identity binding, approval, capability admission, actual mutation, and any future canonical effect.

## 2. Source and lexical model

| Element | v0.1 candidate rule | Security purpose |
|---|---|---|
| Encoding | UTF-8 without a BOM | Aligns source transport with the current interop profile |
| Newlines | LF, CRLF, and CR are lexical line breaks; they are not semantic differences | Formatting does not change meaning |
| Keywords | Lowercase ASCII and case-sensitive | Avoids locale and Unicode keyword ambiguity |
| Local declaration names | ASCII lowercase identifier: `[a-z][a-z0-9_]{0,63}` | Keeps symbolic references free of confusable Unicode forms |
| External identity / namespace / lineage references | Quoted Identifier Literal validated by the current NFC, non-empty, untrimmed, 256-code-point interop rule | Keeps stable external references compatible with current contracts |
| Strings | JSON-style quoted strings, no unpaired surrogate; accepted text must satisfy NFC admission | Avoids invisible-normalization and malformed-Unicode drift |
| Comments | `//` through end of line only; comments are non-semantic | Keeps parsing deterministic without nested-comment rules |
| Whitespace | Non-semantic except where needed to separate tokens | Equivalent formatting maps to the same IR |
| Declaration boundary | Semicolon required after every declaration and field | Avoids newline-sensitive ambiguity |
| Source limits | `CANDIDATE_LIMIT`: 1 MiB source, 256-character external identifier, 4 KiB string literal, 128 nesting depth, 1,024 declarations, 100 diagnostics | Bounds future parser denial-of-service surface |

The candidate source model prohibits a byte-order mark, locale-sensitive parsing, implicit current time, filesystem inference, network lookup, hidden global state, and host-language-dependent ordering. Source locations may contain line, column, byte offset, and code-point offset for diagnostics, but locations are not semantic identity and do not enter canonical IR.

## 3. Semantic types

| Semantic type | Source representation | AST / IR representation | Equality and ownership meaning |
|---|---|---|---|
| `AgentIdentity` | Quoted external identifier literal | Typed identity reference | Equal only to another `AgentIdentity`; textual equality does not grant authority |
| `RuntimeInstanceIdentity` | Quoted external identifier literal | Typed runtime-instance reference | Must bind to the declared agent / context; cannot be substituted by a changed label |
| `MemoryNamespace` | Quoted external identifier literal plus typed runtime owner | Typed namespace reference | Must remain bound to its owning runtime; AION and Astra namespaces cannot cross silently |
| `ProvenanceReference` | Named provenance declaration | Source-derived provenance reference | Attribution and uncertainty are explicit; provenance is not approval |
| `CapabilityRequirement` | Bounded capability token | Required capability list | Requested capability is not capability admission |
| `ApprovalRequirement` | Scope and typed target reference | Required authority record | Requirement is not approval evidence and is non-inheritable |
| `RuntimeEffect` | Enumerated declaration | Effect classification | Describes intended class only; actual mutation remains external |
| `CanonicalEffect` | Only `none` in source | `NONE` in IR | No source construct can request or grant canonical write |
| `LifecycleRequirement` | Start / stop requirement for a typed runtime reference | Requirement record | Source has no `from_state`, `to_state`, atomicity claim, or successful outcome |
| `Version` | Explicit language header and referenced profile version | Version fields | Incompatible versions fail closed |
| `Timestamp` | Not generated by source v0.1 | Future external diagnostic / evidence field | No implicit current time in source semantics |

Semantic types may serialize as strings in IR, but they are not semantically substitutable merely because they use the same host representation.

The current `IndividualRuntimeContext` contract also carries `memory_stream_id`, `event_lineage_id`, `canonical_state_reference`, and `genesis_root_id`. The v0.1 native IR intentionally does not turn those fields into source-level declarations because Event / Lineage, canonical-state, and Genesis semantics are not mature enough to freeze. A future adapter may attach an externally governed context reference, but source text must not manufacture or complete that binding.

The lifecycle mapping is deterministic but remains request-only: source `transition: start` maps to the existing request event type `runtime.started`, and source `transition: stop` maps to `runtime.stopped`. The mapping does not emit `from_state`, `to_state`, `event_sequence`, `event_hash`, or successful outcome fields.

## 4. Candidate declaration families

| Declaration | Purpose | Native source? | Validated IR? | Execution / authority boundary |
|---|---|---:|---:|---|
| `runtime` | Declares a typed AION or Astra runtime reference | Yes | Yes | Cannot bind or start a runtime |
| `provenance` | Declares source / attribution / uncertainty metadata | Yes | Yes | Cannot manufacture verified provenance or approval |
| `memory namespace` | Declares a typed namespace owned by a declared runtime | Yes | Yes | Cannot read, write, mutate, or cross namespaces |
| `lifecycle` | States a lifecycle transition requirement | Yes | Yes | Cannot claim state, atomicity, or success |
| `operation` | Describes a bounded non-executable request profile | Yes | Yes | Cannot invoke a tool or runtime action |
| `requires approval` | States target and scope requirement | Yes | Yes | Cannot state approval is satisfied |
| `requires capability` | States a bounded required capability | Yes | Yes | Cannot grant capability |
| `canonical_effect` | States the only admitted effect value, `none` | Yes | Yes | Cannot expand canonical authority |
| Event / lineage | Abstract future reference only | No persisted syntax | Provisional metadata only | Hash framing remains unresolved |
| Recovery / checkpoint | Future requirement / IR reference only | No execution syntax | Provisional metadata only | Cannot restore state |

## 5. AST model

The AST reflects source structure before semantic validity. It contains source locations and raw spelling where useful for diagnostics, but it does not contain runtime facts that the source did not provide.

| AST node | Required syntax-derived fields | Excluded runtime facts |
|---|---|---|
| `DocumentNode` | Language version header, ordered declarations, document span | Authorization, execution result |
| `RuntimeDeclarationNode` | Local name, runtime kind, agent literal, instance literal, context references, declared canonical effect | Identity binding success, admission result |
| `ProvenanceDeclarationNode` | Local name, source kind, attribution literal, uncertainty | Provenance verification result |
| `MemoryNamespaceDeclarationNode` | Local name, owner local reference, namespace literal, effect declaration | Access right, mutation outcome |
| `LifecycleRequirementNode` | Runtime local reference, requested transition, requirements, effect declaration | Current state, derived state, atomicity, committed event |
| `OperationRequirementNode` | Local name, operation kind, runtime local reference, requirements, effect declaration | Tool invocation, result, runtime mutation |
| `ApprovalRequirementNode` | Scope literal and target local reference | Human presence, account evidence, approval satisfaction |
| `CapabilityRequirementNode` | Capability token | Grant or admission result |
| `EffectDeclarationNode` | Runtime effect class and canonical effect literal | Actual state change |

## 6. Semantic-analysis model

Static analysis answers only **“Is this source semantically well-formed under language v0.1?”** It does not answer whether an operation is authorized or executable now.

| Stage | Checks | Rejection codes |
|---|---|---|
| Lexical admission | UTF-8, BOM, comments, keywords, local names, identifier-literal size, Unicode validity | `LEXICAL_ERROR`, `RESOURCE_LIMIT_EXCEEDED` |
| Grammar parsing | Header, declaration boundaries, blocks, fields, punctuation, no ambiguity | `PARSE_ERROR` |
| Symbol analysis | Duplicate local names, unresolved local references, declaration-kind compatibility | `DUPLICATE_DECLARATION`, `UNKNOWN_SYMBOL`, `TYPE_ERROR` |
| Type / identity analysis | Typed reference use, runtime-kind / namespace owner consistency, cross-agent substitution | `TYPE_ERROR`, `IDENTITY_MISMATCH` |
| Version analysis | Exact language and referenced profile version | `UNSUPPORTED_VERSION` |
| Effect analysis | Canonical effect equals `NONE`; effect combinations are allowed | `INVALID_EFFECT` |
| Authority analysis | No self-authenticating approval, grant, owner, bypass, or administrator construct | `AUTHORITY_REQUIRED`, `CAPABILITY_DENIED` |
| Contract maturity analysis | Blocked Event / Lineage / recovery semantics are not claimed as final | `FOUNDATION_CONFLICT`, `PROVISIONAL_SEMANTIC` |

A successful analysis emits validated IR only. It does not attach `approval_satisfied`, `capability_granted`, `identity_bound`, `runtime_admitted`, `state_mutated`, `event_committed`, or any canonical write field.

## 7. Effect, approval, and capability model

Every validated declaration receives one semantic classification:

| Classification | Meaning | Authorization status |
|---|---|---|
| `PURE_DECLARATION` | Describes static architecture / provenance / typed references only | No runtime request |
| `RUNTIME_READ` | Requests a future read-class operation | Requires future governed admission |
| `RUNTIME_MUTATION_REQUEST` | Describes a future non-canonical mutation request | Requires future governed admission |
| `APPROVAL_REQUIRED_REQUEST` | Requests an operation that carries an explicit approval dependency | Approval remains external evidence |
| `CAPABILITY_REQUIRED_REQUEST` | Requests an operation with a bounded capability dependency | Capability remains external admission |
| `PROVISIONAL_UNEXECUTABLE` | References a domain whose shared contract is incomplete | Never executable in v0.1 |

The only source-level canonical-effect form is `canonical_effect: none;`, which emits `canonical_effect: "NONE"` in IR. Any attempt to request `write`, `promote`, or equivalent canonical effect is an `INVALID_EFFECT` error. Approval requirements may name a scope and target but cannot assert that a person is present, an account is a person, an approval is permanent, or approval has been inherited.

## 8. Error model and IR serialization

Language diagnostics use stable semantic codes: `LEXICAL_ERROR`, `PARSE_ERROR`, `TYPE_ERROR`, `UNKNOWN_SYMBOL`, `DUPLICATE_DECLARATION`, `UNSUPPORTED_VERSION`, `IDENTITY_MISMATCH`, `AUTHORITY_REQUIRED`, `CAPABILITY_DENIED`, `INVALID_EFFECT`, `INVALID_TRANSITION`, `FOUNDATION_CONFLICT`, `PROVISIONAL_SEMANTIC`, and `RESOURCE_LIMIT_EXCEEDED`.

Where a future adapter exposes errors through the current AION Error Envelope, it maps these codes to the existing candidate categories without treating host-language exception text as a portable semantic. Canonical IR uses the current candidate Interoperability Profile: UTF-8, strict JSON, NFC admission, safe integers, deterministic object ordering, and `canonical_effect = NONE`. A language design conflict with that profile must be reported as `FOUNDATION_CONFLICT`; this milestone does not change the profile.

## 9. Non-executable invariants

The language has no functions, loops, recursion, variables, modules, imports, dynamic evaluation, bytecode, VM, native-call, filesystem, process, plugin, socket, network, package, compiler, or interpreter semantics. It cannot start a runtime, mutate memory, invoke a tool, create approval evidence, grant capability, bind identity, recover a checkpoint, compute event hashes, or rewrite historical records.

```text
SOURCE != AUTHORIZATION
AST != AUTHORIZATION
VALIDATED_IR != AUTHORIZATION
CANONICAL_EFFECT = NONE
LANGUAGE_RUNTIME_EXECUTION = NOT_AUTHORIZED
```
