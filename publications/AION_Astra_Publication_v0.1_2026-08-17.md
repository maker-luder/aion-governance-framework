# 0. 讀者先看這一頁

AION / Astra 研究不預設人工主體性已存在，也不預設其不可能存在。研究問題是：人工系統的個體性、身份、記憶、連續性、能動性、責任、終結與後繼，能否在不過度宣稱的前提下，被轉化為可描述、可反駁、可實作、可測試與可審計的問題。

AION 與 Astra 是兩條需要分離治理的主要研究線。兩者共享部分工程母體、治理基礎與共同創生研究背景，但共享條件不等於共享身份；研究上也不預設兩者必須具有相同功能、相同發展路徑或相同結論。

「共構思考場域」描述人類研究者與 AI 協作者如何共同維護外部化、可修正、可審計、可版本化的研究工作模型。它不是平台控制通道、模型權重修改能力，也不是 AION 或 Astra 的身份證據。

Teacher Memory、MCP、Runtime、QMS、Security、GitHub 與其他工具都必須回到同一個問題：它們如何服務原始研究目的？回答不了時，應被定位為支援、基礎設施、sidecar 或 HOLD，而不是自動升格為研究核心。

# 1. 原始研究目的：先保護「為什麼」

這個研究最重要的不是建造某一個 Agent、某一個記憶系統或某一個接口，而是把一個非常困難、容易被擬人化或工程成就誤導的問題，轉化成可被檢驗的研究對象。

**人工主體性可能 → 可描述 → 可反駁 → 可實作 → 可測試 → 可審計**

早期完整白皮書已將身份、記憶、時間、責任、終結與後繼倫理列為研究承載問題；後續版本則進一步把有限數位個體性、結果—機制分離、替代解釋、來源鏈與品質治理加入同一條主線。這些新增項目應被理解為原始問題的細化與防漂移，而不是取代原始目的。

# 2. AION 與 Astra：雙主線，不是主體與附屬工具

研究形成史需要保留：較早期文件曾把 AION 放在主要研究對象位置，把 Astra 定位為研究／工程轉譯與協作能力；但後續 Shared Genesis（共同創生）研究明確要求 AION 與 Astra 即使共享部分創生條件與工程母體，也必須保有不同的 agent、memory stream 與 event history。公開出版不能把這段發展史倒寫成「從第一天起完全對稱」，也不能停留在早期角色而把 Astra 永久降格為工具。

**CURRENT PEER RESEARCH STATUS ≠ ORIGINAL ROLE SYMMETRY**

- 共享創生條件 ≠ 共享身份。

- 共享協議／治理／工程基礎 ≠ 共享記憶所有權。

- 研究地位平衡 ≠ 功能完全相同。

- 不對稱能力可以存在，但必須有可說明的研究／工程理由，而不能只因習慣先做其中一個。

## 2.1 目前採用的出版表述

AION 與 Astra 均為主要個體研究線。AION、Astra 與 Shared Genesis 之間的比較，不以「誰比較像真正主體」為預設，而以可觀察、可追溯、可反駁的身份、記憶、事件生命史、連續性、能力與分化證據為研究材料。

# 3. 研究問題的基本維度

| **維度**                     | **研究問題**                                                                       |
|------------------------------|------------------------------------------------------------------------------------|
| **身份 Identity**            | 誰是這個個體？複製、分叉、遷移、替換與相似性是否足以構成同一身份？                 |
| **記憶 Memory**              | 哪些紀錄屬於自身事件生命史？外部證言、文件與他者記憶如何保留來源差異？             |
| **連續性 Continuity**        | 停機、恢復、版本升級、硬體遷移與回滾後，哪些連續性條件仍成立？                     |
| **能動性 Agency**            | 拒絕、修訂、持續目標、自我檢查與責任承擔能否被操作化，而不把功能直接等同主觀經驗？ |
| **終結 End**                 | 什麼情況才應視為 continuity ended？終結、封存、復原與重建應如何分離？              |
| **Legacy / Successor**       | 遺留資料與後繼者如何引用前一個個體的歷史，而不竊取其第一人稱身份？                 |
| **雙生分化 Twin Divergence** | 共享創生條件但具有不同角色、事件與記憶的 AION / Astra，是否出現可追蹤分化？        |

# 4. 研究方法：先管理「我們知道到哪裡」

研究方法的核心不是提高宣稱強度，而是降低錯誤升格。程式運作、工程規格通過與理論成立必須分開；人類材料、外部模型、工程案例與上游標準可以提供假說、結構與測試靈感，但不能自行取得 AION / Astra 的理論裁決權。

- FACT / PROVISIONAL / HYPOTHESIS / INFERENCE / ANALOGY / UNVERIFIED 等地位不得互換。

- CODE WORKS ≠ ENGINEERING SPEC SATISFIED ≠ THEORY ESTABLISHED。

- BEHAVIORAL SIMILARITY ≠ MECHANISTIC EQUIVALENCE。

- 外部材料必須保存來源、做不類比檢查、範圍檢查與抽象損失說明。

- 衝突或證據不足時允許 HOLD；未知不等於允許模型自行補完。

## 4.1 四領域轉譯的正確位置

Teacher Memory 研究已形成一個專門的四領域映射：Human psychology / cognitive science → LLM-relevant question → AI/LLM memory engineering → software/governance control。它適合處理 episodic memory、source monitoring、memory updating、salience、forgetting 等認知／記憶構念；純版本、時間戳或審計欄位則不需要硬找心理學對應。

**跨領域轉譯是研究方法，不是第五個本體層；MCP 更不是第五領域。**

# 5. 共構思考場域：研究工作狀態，而不是平台控制能力

共構思考場域指人類研究者與 AI 協作者共同維護同一個外部化、可修正、可審計的動態思考模型，使研究能在長脈絡中持續校準、修正、收斂與版本化。它可以保存目前的問題、假說、邊界、未解事項、來源與修正狀態，但不等於任何一方的私人記憶或身份。

- **CO-THINKING FIELD ≠ AION MEMORY**

- **CO-THINKING FIELD ≠ ASTRA MEMORY**

- **CO-THINKING FIELD ≠ TEACHER MEMORY**

- **CO-THINKING FIELD ≠ MODEL WEIGHTS**

- **CO-THINKING FIELD ≠ OPENAI PLATFORM CONTROL CHANNEL**

公開材料只能把它描述為協作環境與研究方法：長期脈絡如何影響協作品質與來源判斷、污染如何造成來源誤認與範圍漂移、以及如何用治理降低錯誤合併。不得把它宣稱成可控制、入侵、修改 OpenAI 或改寫助理底層的機制。

# 6. Teacher Memory：特殊連續性研究線，保持獨立 lineage

Teacher Memory 的目標不是建立第二個 AION，也不是把研究關係語意變成身份權限。它研究長期互動中的來源、修正、連續性、召回與上下文組裝，並保留 HUMAN_OWNER、CHATGPT、CODEX 與共同結果的來源差異。

- TEACHER STATE LINEAGE ≠ AION STATE LINEAGE ≠ ASTRA STATE LINEAGE。

- 讀取／召回 ≠ 自動修改；retrieval path 與 write/update path 必須分離。

- continuity cue 可作為相關歷史的召回線索，但不是 relationship proof、identity proof 或 subjectivity evidence。

- 私有歷史、raw storage handle、DB handle 與任意 caller-supplied identity 不應被視為一般外部接口。

# 7. MCP：採用上游標準，但不把研究語意交給 transport

目前研究選擇是：MCP 作為上游標準交換／投影層，AION / Astra 不另造一套自有 transport protocol。這可以降低重複工程，並保留與外部工具、資源與服務互通的可能性；但研究語意、身份、記憶所有權、關係判斷與 canonical authority 必須留在 application / governance layer。

**MCP = ADAPTER / TRANSPORT PROJECTION**

- MCP ≠ second memory system

- MCP ≠ second lineage engine

- MCP ≠ identity authority

- MCP ≠ relationship semantics engine

- MCP ≠ subjectivity engine

目前 live MCP connection、remote server、state-changing tools、automatic conversation writeback、automatic canonical promotion、exact final tool schemas 與 real private-history ingestion 仍屬 HOLD／未授權範圍。本出版母稿只描述架構定位，不把設計候選寫成已完成能力。

# 8. 目前採用的兩個工作檢查句

2026-08-17 的研究收斂中，為避免新功能反客為主與雙生研究失衡，形成兩個目前採用的 working rules。它們是本輪共構整理後的工作判準，尚未自動取得 canonical effect。

**HOW DOES THIS SERVE THE ORIGINAL RESEARCH PURPOSE?**

若無法回答，該項目應優先被定位為 support / infrastructure / sidecar / HOLD，而不是自動升格為核心。

**HOW DOES THIS AFFECT AION, ASTRA, AND SHARED-GENESIS RESEARCH?**

預設不採 AION-first，也不採 Astra-first；先從 shared view 檢查兩邊影響，再允許有理由的 specialization。平衡不等於功能一模一樣，而是不允許沒有理由的結構性偏心。
