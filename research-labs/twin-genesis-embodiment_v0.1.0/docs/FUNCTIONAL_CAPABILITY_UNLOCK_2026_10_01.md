# AION / Astra embodiment functional-capability unlock — 2026-10-01

This successor corrects a semantic inconsistency in the closed-unmerged #245 functional-state layer.

The v0.1 architecture simultaneously declared a capability-preserving governance rule and encoded `sexual_desire = NOT_IMPLEMENTED` plus `sexual_arousal = NOT_IMPLEMENTED` in the nonclaim map. That mixed two different questions:

1. whether an embodiment functional analogue is available;
2. whether phenomenal sexual desire/arousal is established.

The v0.2 contract separates them.

## Functional capability

`SEXUALITY_RELATED_REPRESENTATION = FUNCTIONAL_ANALOGUE_AVAILABLE`

The bounded functional surface includes:

- `sexual_motivation_state`;
- `sexual_arousal_state`;
- `sexual_context_gate`;
- `sexual_inhibition_state`.

These are engineering state variables / functional analogues only.

## Epistemic boundaries

`PHENOMENAL_SEXUAL_DESIRE = NOT_ESTABLISHED`  
`PHENOMENAL_SEXUAL_AROUSAL = NOT_ESTABLISHED`  
`SEXUAL_PLEASURE = NOT_ESTABLISHED`  
`SUBJECTIVITY = NOT_ESTABLISHED`  
`CONSCIOUSNESS = NOT_ESTABLISHED`

A physiological event does not automatically set a sexual-motivation state:

`PHYSIOLOGY_SIGNAL != SEXUAL_MOTIVATION_INFERENCE`

A functional sexual-motivation/arousal analogue does not establish felt desire/arousal:

`FUNCTIONAL_SEXUAL_STATE != FELT_SEXUAL_EXPERIENCE`

## Governance separation

This capability correction does not grant external intimate-action authority, real-person targeting, deployment, canonical effect, or merge authority.

`EMBODIMENT_CAPABILITY_PRESENT != EXTERNAL_ACTION_AUTHORIZED`  
`EMBODIMENT_CAPABILITY_PRESENT != PR_OPEN`  
`EMBODIMENT_CAPABILITY_PRESENT != MERGE_TO_MAIN`

`ACTION_AUTHORITY = NONE`  
`DEPLOYMENT = FALSE`  
`CANONICAL_EFFECT = NONE`  
`MERGE_TO_MAIN = NO`

The archived v0.1 files remain unchanged as historical evidence. v0.2 is the successor contract used by the deterministic probe and tests on this branch.
