# AION／Astra Identity, Lineage and Fork Governance — Candidate v0.1.0

This offline candidate separates **project identity** from model weights, adapters, runtimes, devices, prompts, and memories.

- Canonical name remains `AION／Astra`; Qwen, Llama, Breeze and other names are upstream model families.
- Ollama is a runtime, not the AION／Astra identity.
- LoRA, ablation, quantization, merge and prompt changes are Capability Artifact modification methods.
- A Capability Artifact can be versioned, compared, disabled or rolled back, but never inherits project identity or permissions.
- Every Research Fork receives a new ID and defaults to denied identity, canonical, memory, tool and relationship inheritance.
- A SHA-256 chain demonstrates record continuity and integrity; it does not prove subjectivity.
- Memory continuity does not prove consciousness or subjectivity.
- Perspective Channels preserve analysis provenance and disagreement; they are not private experiences.
- The external “twin genesis” proposal is a conceptual source only and has no canonical effect.
- `subjectivity_conclusion=NOT_ESTABLISHED`; no model modification occurs in this phase.

## Integration

The component uses one Capability Registry and an adapter for Astra Language Core nodes. It does not create a second model registry. Existing frozen, baseline, canonical, release and QA HOLD files remain unchanged.
