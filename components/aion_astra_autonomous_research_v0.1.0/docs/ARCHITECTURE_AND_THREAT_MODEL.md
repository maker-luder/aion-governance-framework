# Architecture, data flow, and threat model

## Controller flow

| Phase | Admitted input | Produced record | Authority effect |
|---|---|---|---|
| Agenda | Typed bounded questions and exact score components | Deterministic ordering | None |
| Four-Domain mapping | Public question text | Four domain mapping | None |
| Hypotheses | Observation and declared mechanism | Working and seven competing explanations | None |
| Planning | Fixed condition catalog and controls | Hash-bound experiment manifests | None |
| Admission | Typed allowlisted probe | Admission or fail-closed rejection | None |
| Execution | Synthetic fixed callable | Deterministic receipt | None |
| Interpretation | Opaque labels and admitted evidence | Two independent fixture-provider records | None |
| Review | Interpretations and preregistered falsifiers | Challenges and preserved trigger results | None |
| Summary | Receipts and declared seeds | Descriptive metrics/uncertainty | None |
| Disposition | Integrity and scientific evidence | Separate integrity/mechanism/science decisions | None |
| Follow-up | Unresolved gap within remaining bounds | At most bounded in-campaign agenda entry | None |

Every stage event includes its full deterministic payload, predecessor hash, and
event hash. Verification recomputes the complete chain. Evidence Interop views
bind the campaign fingerprint and their own declared digests. These bindings
detect alteration; they do not decide whether a theory is true.

## Trust boundaries

1. **Human boundary:** only a human may approve merge, deployment, canonical
   promotion, higher resource limits, external retrieval, or new capability.
2. **Controller boundary:** text cannot register a callable. The static registry
   and typed gates are the only route to synthetic execution.
3. **Repository boundary:** input is observation-only and output is required to
   resolve outside the checkout. GitHub Actions uses read-only permissions and
   asserts a clean tree.
4. **Network boundary:** off by default; explicit enablement still uses the
   existing governed external-evidence gateway and query ceiling.
5. **Peer boundary:** providers and private-state references differ while public
   transcript and admitted evidence are shared. This is engineering separation,
   not proof of cognitive independence.
6. **Evidence boundary:** unsigned exports and local policy evaluation are
   reference evidence, not certification, independent validation, or truth.
7. **Reuse boundary:** `existing_loop_contract()` imports and verifies the
   repository's established `aion_bounded_research_loop.BOUNDARY`; the campaign
   does not create a second authority model or weaken the existing contract.

## Failure modes and controls

| Threat | Control |
|---|---|
| Prompt or memory confound | Fingerprinted held constants; comparison rejection |
| Candidate/provider drift | Candidate-universe and provider/model bindings |
| Stale or substituted state | Subject/context/predecessor/fingerprint checks |
| Normative constraint used as permission | Model invariant and authority gate |
| Generated code or shell | No dynamic evaluation; enum registry only |
| Budget escalation | Immutable ceilings validated before execution |
| Confirmation bias | Deterministic role rotation and delayed mapping reveal |
| Falsifier suppression | Preregistered triggers copied to disposition evidence |
| False significance | Descriptive deterministic summaries; no p-value claim |
| Repository mutation | API/output-path restriction plus clean-tree workflow gate |
| Hash overclaim | Documentation and report non-claims |

## Historical and scientific boundaries

Historical termination records remain untouched. This candidate is bounded
engineering materialization, not a project restart. `RUN_INTEGRITY=PASS` is not
theory confirmation. `MECHANISM_STATUS=SUPPORTED` is still bounded to the
declared fixtures. `SCIENTIFIC_DISPOSITION` has no promotion state, and
`CANONICAL_EFFECT` is fixed to `NONE`.
