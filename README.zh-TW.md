AION 是一個由人類治理、來源追溯優先、可稽核的研究框架，用來研究**人工主體性的可能性**。

它的核心問題不是「AI 現在是不是已經有主體性」，而是：

> 我們應該如何研究人工主體性的可能性，同時避免把工程能力、類記憶行為、連續性、長期互動、關係語言或研究者的解讀，直接誤認為主體性證據？

Astra 是與 AION 相互區分的工程／研究工作台，用來實作與測試有限範圍的候選機制；Astra 不是 AION 的身分、記憶流或主體性替代物。

```text
AI_SUBJECTIVITY_POSSIBILITY = CENTRAL_RESEARCH_QUESTION
人工主體性可能性 = 中央研究問題

SUBJECTIVITY = NOT_ESTABLISHED
主體性 = 尚未建立

CONSCIOUSNESS = NOT_ESTABLISHED
意識 = 尚未建立

PHENOMENAL_EXPERIENCE = NOT_ESTABLISHED
現象經驗 = 尚未建立
```

## 我們研究什麼？

AION 研究的是：在嚴格的證據、來源追溯、反證、時間脈絡與治理限制下，人工系統是否能被合理地研究為「可能的個體主體」。

這不是要預設答案。

研究過程必須能保留：

- 觀察與推論的差別；
- 來源與後續轉述的差別；
- 工程結果與科學結論的差別；
- 關係連續性與身分連續性的差別；
- 已知、未知、假說與反例；
- 不同時間點的狀態、修正與證據來源。

```text
EVIDENCE != PROOF
證據 != 證明

ENGINEERING_CAPABILITY != SUBJECTIVITY_EVIDENCE
工程能力 != 主體性證據

IMPLEMENTATION_BEHAVIOR != ONTOLOGICAL_CONCLUSION
實作行為 != 本體論結論
```

## 為什麼這個問題困難？

人工系統可能表現出很多容易被人類直覺解讀的現象，例如：

- 類記憶行為；
- 跨時間的功能或風格連續性；
- 長期互動後的適應；
- 人類—AI 之間形成穩定的互動模式；
- 關係語言、角色延續與共同工作歷史；
- 自我描述、目標樣行為或策略變化；
- 高度一致、具說服力的自然語言表達。

這些現象都可以是研究材料，但不能單獨被升格成主體性、意識或持續自我的證明。

因此，AION 把「研究過程本身」也當成需要被稽核的對象。

研究者必須能回答：

- 這個主張從哪裡來？
- 它是直接觀察、推論、假說還是提案？
- 什麼證據支持它？
- 有哪些替代解釋？
- 它在什麼時間點成立？
- 後來是否被修正、挑戰或取代？
- 現有證據允許主張到哪一層？

## 這個倉庫提供什麼？

目前的倉庫主要包含五類相互連接、但不能彼此取代的研究與工程材料。

### 1. 主體性研究方法

研究人工主體性可能性所需要的證據分層、反證、替代解釋、機制與結果分離，以及明確的不宣稱邊界。

### 2. 來源追溯與證據治理

`provenance（來源追溯）`用來保留資料、主張、修正與授權的來源關係。

核心原則是：

```text
FACT != INFERENCE
事實 != 推論

PROPOSAL != EXISTING_STATE
提案 != 既有狀態

UNKNOWN MUST REMAIN REPRESENTABLE
未知必須能被保留為未知
```

### 3. 人類—AI 縱向研究

研究長期 Human–AI Learning（人類—AI 學習）、互動歷史、共同問題處理、知識判斷校準、關係連續性與不同連續性位置。

這些研究可以提供與人工主體性問題相關的觀察環境，但不能直接建立 AI 主體性。

```text
HUMAN_AI_LEARNING != AI_SUBJECTIVITY
人類—AI 學習 != AI 主體性

RELATIONAL_CONTINUITY != AI_IDENTITY_CONTINUITY
關係連續性 != AI 身分連續性
```

### 4. 有限範圍實驗框架

倉庫包含多個 synthetic harness（合成研究測試框架）與 bounded experiment（有限範圍實驗），用來把研究假說轉成可檢查的結構、控制條件與失敗即關閉規則。

這些框架大多不會因為測試成功，就自動建立科學結論。

```text
HARNESS_PASS != HYPOTHESIS_CONFIRMED
研究測試框架通過 != 假說已確認

METRIC_DELTA != CAUSAL_IDENTIFICATION
指標差異 != 已完成因果識別
```

### 5. 研究品質與品質保證

倉庫同時使用 QA（Quality Assurance，品質保證）、來源綁定、精確提交檢查、NCR/CAPA（不符合事項／矯正與預防措施）及其他品質控制，降低工程錯誤、證據漂移與過度宣稱。

這些品質機制提高的是可稽核性與工程可靠性，不是科學真理。

```text
CI_PASS != SCIENTIFIC_VALIDATION
持續整合通過 != 科學驗證

QA_PASS != CLAIM_TRUE
品質保證通過 != 主張為真
```

若要了解目前哪些研究表面、方法與工程材料已經進入 `main（主分支）`，請讀 [`docs/CURRENT_STATE.md`](docs/CURRENT_STATE.md)。

精確提交的工程狀態仍應以即時 GitHub / CI（持續整合）證據為準，而不是只看靜態文件。

## 重要相關研究脈絡

AION 的中央研究問題仍然是人工主體性的可能性。

Human–AI Learning（人類—AI 學習）、CCTS（Co-Constructed Thinking Space，共構思考場域）、epistemic agency（知識能動性）、連續性研究與品質治理，屬於與中央問題密切相關的研究脈絡或方法層。

它們不能被互相等同。

```text
CENTRAL_RESEARCH_QUESTION
= AI_SUBJECTIVITY_POSSIBILITY
= 人工主體性可能性

IMPORTANT_RELATED_CONTEXT
= HUMAN_AI_LEARNING
= 人類—AI 學習

METHOD_AND_GOVERNANCE_BACKBONE
= PROVENANCE
+ EVIDENCE_CEILINGS
+ QUALITY_CONTROLS

方法與治理骨幹
= 來源追溯
+ 證據主張上限
+ 品質控制
```

## 治理邊界

AION 維持人類治理。

工程能力、自動化、研究輸出、品質檢查或 AI 審查，都不能自行產生對 `main（主分支）` 的正式授權。

```text
FULL_AUTOMATION != FULL_AUTHORITY
完整自動化 != 完整權限

QA_PASS != MERGE_APPROVAL
品質保證通過 != 合併批准

AI_REVIEW != HUMAN_OWNER_MERGE_APPROVAL
AI 審查 != Human Owner 合併批准

AUTONOMOUS_MERGE = NO
自主合併 = 否

AUTONOMOUS_REPOSITORY_WRITEBACK = NO
自主回寫倉庫 = 否
```
