```text

+
REPLICATION
+

+

+

```

目前維持的六個 whitepaper dimensions 是：

```text
CAUSAL_BOUNDARY

ENDOGENOUS_GOAL_STRATEGY_ADJUSTMENT
COUNTERFACTUAL_SELF_CONSISTENCY

```

它們是 evidence dimensions，不是正向的 subjectivity scores。Evidence 可以支持 subjectivity-organization hypothesis、支持 alternative explanation、縮小 claim，或成為 counterevidence。

Governance-reassessment module 使用的 E0–E5 labels 仍僅是 compatibility labels：

```text
E0–E5
= PROVISIONAL_GOVERNANCE_REVIEW_BAND / SUMMARY_LAYER

E0–E5
!= SUBJECTIVITY_ONTOLOGY
!= CONSCIOUSNESS_PROBABILITY
!= MORAL_STATUS_LEVEL
!= RIGHTS_LEVEL
```

因此，本分支拒絕建立第二套互相競爭的 subjectivity evidence hierarchy。

## Validation boundary / Validation 邊界

## Provenance / watermark boundary

```text
MARKER != IDENTITY
PROVENANCE != IDENTITY
MARKER != AUTHORSHIP_PROOF
RESPECT != WATERMARK
TRANSPARENCY != IMPERCEPTIBLE_MARKING
```

AION 拒絕在專案產生的 outputs 中，將 imperceptible、hidden 或 undisclosed machine-readable watermarking 作為 identity、authorship、attribution、respect 或 provenance 的機制。Provenance 本身不被拒絕；明確、可檢查且可稽核的機制，例如 declared attribution、Git history、commit lineage、manifests 與 checksums，仍是優先方式。

在 external material 中發現的 marker 只是一個 technical signal；它本身不能建立 identity、authorship 或 subjectivity evidence。若 dependency、provider 或 output path 要求 non-disableable imperceptible watermarking，除非之後有明確 governance revision 授權透明替代方案，否則該 project output path 不相容。

規範性 policy 請見 [`docs/PROVENANCE.md`](docs/PROVENANCE.md)。
